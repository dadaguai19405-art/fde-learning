# 3 分钟演示脚本

## 演示前检查

- 天气应用、RAG 应用可以打开；
- DeepSeek Key 和 Postgres Secrets 已配置；
- RAG 页面可以正常回答；
- 反馈看板可以读取反馈；
- 准备一个已知问题，例如“高温天气怎么补水？”；
- 准备一个拒答问题，例如“今天会下雨吗？”；
- 准备一个未知问题，例如“明天股票会涨吗？”。

## 0:00–0:25 项目介绍

“这是一个从零构建的 FDE 实践项目。它把公开天气 API 的数据存入 Supabase Postgres，再通过 Streamlit 展示，并接入 DeepSeek 生成出行建议和 RAG 知识回答。项目还包含反馈闭环、评测和 CI。”

## 0:25–1:10 天气应用

1. 打开天气应用；
2. 选择“上海”；
3. 点击获取天气；
4. 展示温度、风速、历史记录和趋势图；
5. 说明数据写入 Supabase，而不是临时本地文件。

讲解点：

- API → Postgres → Streamlit 的数据链路；
- 应用使用受限数据库用户，不是超级用户。

## 1:10–2:00 RAG 助手

1. 打开 RAG 页面；
2. 问“高温天气怎么补水？”；
3. 展示一般建议、当前天气适用性和引用来源；
4. 再问“今天会下雨吗？”；
5. 展示系统明确说“根据现有资料无法判断”；
6. 再问“明天股票会涨吗？”；
7. 展示无关问题不会错误检索天气资料。

讲解点：

- 先检索，再生成；
- 回答必须带引用；
- 资料不足时拒答，不编造。

## 2:00–2:30 反馈闭环

1. 对回答点击 👍 或 👎；
2. 打开反馈看板；
3. 展示好评率、差评分类和处理状态；
4. 说明差评可以标记为“已修复”并写处理备注；
5. 说明一条真实差评如何被转成回归测试。

## 2:30–3:00 工程质量

展示 GitHub 仓库：

- CI 绿色；
- 34 个测试；
- 84.62% 覆盖率；
- ruff 检查通过；
- README 架构图和案例复盘。

收尾：

“这个项目不是只展示模型调用，而是覆盖了 FDE 交付中的数据接入、云端持久化、权限、安全、AI 质量、用户反馈和回归测试。”
