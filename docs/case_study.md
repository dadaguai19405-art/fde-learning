# 案例复盘：从零构建天气数据与 AI 助手

## 一句话总结

从零开始构建并部署一个面向真实天气数据的小型 FDE 交付项目，覆盖数据接入、Postgres 持久化、LLM 建议、RAG 引用回答、用户反馈、自动化评测和 CI。

## 背景与目标

目标不是做一个“能回答天气问题”的演示，而是练习 FDE 的完整交付链路：

1. 接入外部数据源；
2. 把数据可靠地保存到云端数据库；
3. 用大模型把数据变成用户可执行的结果；
4. 用 RAG 让回答有资料依据；
5. 收集用户反馈并形成改进闭环；
6. 用测试和 CI 防止回归。

## 用户与场景

- 普通用户：查看城市当前天气、趋势和出行建议。
- 内部运营：查看 RAG 回答质量、差评和处理状态。
- 开发者：通过评测集和自动化测试验证改动没有破坏核心行为。

## 约束

- 每天投入约 2 小时，需要可持续的小步交付。
- 使用免费的公开天气 API 和免费云资源。
- 不把 API Key、数据库密码或用户数据提交到 Git。
- 先做可解释的基线，再考虑更复杂的检索方案。

## 解决方案

### 数据层

- Open-Meteo 提供实时温度和风速。
- 数据写入 Supabase Postgres，避免 Streamlit Cloud 临时文件系统导致数据丢失。
- 应用使用受限用户 `weather_app`，只拥有必要的 DML 权限。
- 反馈表通过 RLS 策略限制应用访问。

### 应用层

- Streamlit 提供天气页面、RAG 页面和反馈看板。
- 天气页面支持城市选择、实时获取、历史表格和趋势图。
- RAG 页面先检索天气知识库，再让模型基于资料回答并返回引用。

### AI 层

- 出行建议使用 DeepSeek，并要求结构化 JSON 输出。
- API 失败时自动回退到规则引擎，保证页面仍然可用。
- RAG 资料不足时明确拒答，不推断当前降雨、空气质量或未来预报。

### 反馈层

- 用户点击 👍/👎，反馈写入 Supabase。
- 差评看板展示问题、回答、引用、模型和处理状态。
- 处理状态支持“待处理 / 已修复 / 忽略”，并保存处理备注。

## 关键取舍

### 1. Postgres 而不是继续使用 SQLite

SQLite 适合本地练习，但不适合 Streamlit Cloud 的临时文件系统。迁移到 Postgres 后，应用重启不会丢失历史记录，也更容易做权限和 RLS。

### 2. 先做关键词 RAG，而不是直接上向量库

关键词检索可解释、无需 embedding 模型、调试成本低，适合先验证“检索 → 引用 → 回答 → 评测”的业务流程。限制是召回依赖关键词，后续可以替换成 pgvector 或 embedding 服务，同时保持同一套评测集。

### 3. 规则回退而不是让页面直接报错

模型 API 可能超时、限流或余额不足。规则引擎作为 fallback，保证核心建议仍然可用，同时在页面上标明“规则回退”，便于排查。

### 4. 反馈不是装饰，而是回归测试来源

一条差评暴露了“一般知识问题被当前天气条件错误拦截”的问题。修复后加入回归测试，避免类似问题再次发生。

| 出行建议评测 | 12/12 |
| RAG 评测 | 9/9 |
| 自动化测试 | 34 passed |
| 覆盖率 | 84.62% |
| 覆盖率门槛 | 70% |
| 代码检查 | ruff 通过 |
| CI | GitHub Actions 通过 |

评测覆盖：

- 高温、低温、大风、升降温；
- 风险等级；
- 回答长度；
- 检索命中；
- 引用有效性；
- 资料不足时拒答；
- 一般知识与当前天气的区分。

## 失败案例与迭代

### 检索被天气上下文污染

问“股票会涨吗”时，上下文里的“风速”命中了天气知识。修复为：只有问题本身属于天气主题时，才把当前天气上下文加入检索。

### 一般知识问题被错误拒答

用户问“高温天气怎么补水”，但当前上海只有 20°C，旧回答直接说“不适用”，没有给一般补水建议，收到差评。修复后先回答一般知识，再补充当前天气是否适用，并加入回归测试。

### 关键词评测的误判

模型说“较热”或“添衣保暖”，语义正确，但测试只认“舒适”或“外套”。通过支持同义词和“任一命中”修正评测标准，同时明确这不是在掩盖模型错误。

## 安全设计

- Secrets 只存在本地和 Streamlit Cloud，不进入 Git。
- 数据库应用用户不是超级用户，不能创建角色、数据库或表。
- `weather` 和 `rag_feedback` 使用 GRANT + RLS。
- 管理员负责建表和迁移，应用只做运行时读写。
- 当前反馈看板没有登录鉴权，生产环境需要补充 SSO 和角色控制。
